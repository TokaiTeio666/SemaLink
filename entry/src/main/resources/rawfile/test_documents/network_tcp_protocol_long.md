# TCP 协议工程：字节流、可靠传输与应用层边界

TCP 向应用提供可靠的双向字节流。字节流没有消息边界，一次发送调用可能被拆成多次接收，也可能与后续发送合并后一次交付。所谓粘包不是 TCP 破坏了消息，而是应用错误地把一次读取当成一个完整业务帧。协议必须自行定义边界，例如固定长度、分隔符、头部长度字段或自描述编码。

长度前缀协议常在头部保存负载字节数。接收方先累计足够的头部，再解析长度并等待完整负载。解析前必须检查负数、零值策略、最大帧长和整数溢出；若长度超过上限，应立即终止会话或进入明确错误状态。读取缓冲区可能同时包含半个帧、一个帧或多个帧，因此解码器需要保留未消费字节。

文本分隔符方案便于调试，但必须处理正文转义和编码问题。若使用换行分隔 JSON，发送方不能让未转义换行穿透帧边界，接收方也不能默认每段字节都是有效 UTF-8。多字节字符可能跨越两次网络读取，直接分别转成字符串会产生替换字符。更安全的做法是在确定完整帧后再统一解码，并把无效编码作为协议错误。

可靠传输建立在序列号、确认、校验和重传之上。发送方保留尚未确认的数据，接收方使用序列号恢复顺序并识别重复片段。超时重传处理确认迟迟未到的情况，快速重传则根据重复确认更早推断丢包。应用看到的可靠性并不意味着无限等待，连接重置、路径中断和本地资源耗尽仍会导致失败。

流量控制保护接收方。接收窗口表示对端当前还能接收多少数据，发送方不能无限制地灌入缓冲区。当应用消费速度下降时，窗口可能缩小甚至归零。工程上若只增加发送线程而忽略对端窗口，吞吐量不会改善，反而会积累更多待发送对象和超时任务。

拥塞控制保护网络路径。慢启动逐步探测容量，拥塞避免在稳定阶段谨慎增长，检测到丢包或显著拥塞信号后降低发送速率。拥塞窗口与接收窗口共同限制在途数据。应用层批量大小、并发连接数和重试策略会影响拥塞行为，因此性能调优应观察往返时延、重传率和实际吞吐，而不是只看本地发送调用耗时。

连接建立需要交换初始序列号并确认双方收发能力。服务端监听套接字接受连接后，每个连接都有独立状态。客户端连接成功仅说明传输层握手完成，不代表应用协议版本、身份或权限已经验证。因此应用常在首帧交换 HELLO、版本、能力和会话标识，并对未知版本返回结构化错误。

优雅关闭与异常断开不同。发送方向连接写端关闭后，已排队数据仍可传输，对端读取到结束标志后知道不会再有新字节；另一个方向仍可能继续工作。若进程崩溃或中间设备丢弃状态，应用可能直到下一次读写或保活超时才发现。会话层必须定义关闭握手、超时和未完成任务的处理方式。

心跳用于发现长时间静默连接是否仍可用，但心跳频率需要权衡。过于频繁会浪费电量和网络资源，过于稀疏又会延长故障发现时间。每次心跳应带可关联标识，收到确认后更新往返时间；不能把普通业务繁忙误判为心跳丢失，也不能在网络恢复后同时触发大量重连形成尖峰。

重连不会自动恢复业务语义。连接中断时，最后一条请求可能未到达、已到达但响应丢失，或已经完成但确认未返回。客户端若盲目重发，可能产生重复写入。请求应包含稳定任务标识，服务端根据幂等规则去重；不能安全重试的操作需要查询状态或人工决策。

超时需要分层。连接超时限制握手等待，读取超时约束对端静默，任务截止时间约束完整业务目标。若下层每次重试都重新获得完整超时时间，总耗时会超过上层预算。更可控的设计是传递绝对截止时间或剩余预算，让 DNS、连接、发送、检索和响应共享同一时间约束。

TLS 在 TCP 字节流之上提供身份验证、机密性和完整性，但不会恢复应用消息边界。握手需要证书校验、算法协商和密钥建立，也可能增加首包延迟。开发环境中跳过证书校验会掩盖真实部署问题，生产代码应明确可信根、主机名校验和证书更新策略，日志不得输出私钥、会话密钥或完整敏感正文。

服务端应对每个连接实施资源上限，包括最大帧长、待处理请求数、缓冲区大小和空闲时间。攻击者或故障客户端可能只发送长度头部却不发送正文，持续占用连接与内存。解码器应在读取早期拒绝非法长度，会话管理器应在超时后释放资源，并用有限速率记录错误，避免日志本身成为负载来源。

协议兼容性需要显式版本。新增可选字段时旧接收方应能忽略，改变字段含义或必填规则则通常需要升级版本。未知消息类型不能被当作普通业务数据继续处理，否则双方状态机会分叉。测试应覆盖旧版本、未知类型、非法 JSON、无效 UTF-8、组合帧、分片帧和对端中途关闭。

网络测试既要验证纯解码逻辑，也要验证真实套接字行为。纯逻辑测试可确定性地喂入任意字节切片，检查缓存、错误与多帧输出；集成测试则在回环或两台设备之间检查连接、超时和断开。性能数据必须说明设备、网络和样本条件，未在真实设备验证的行为应明确标注，不能用模拟结果替代。

一个可维护的 TCP 模块应把传输、协议和业务会话分开。传输层只负责连接与字节收发，协议层负责编解码，状态机负责 HELLO、任务、证据、反馈和关闭顺序。这样既能用模拟传输测试完整闭环，也能替换真实网络实现而不让界面或检索代码直接操作套接字。
