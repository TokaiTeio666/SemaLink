# SemaLink 实时设备状态 UI 设计

## 目标

移除查询页和设备页中的演示性硬编码，使 UI 只展示能够由本地知识库、设备发现结果和 DSK 通道状态证明的数据。设备连接状态必须随控制通道和数据通道事件实时更新，不依赖页面刷新或定时轮询。

## 范围

本次修改包括：

- 查询页的可用设备摘要、查询范围、查询步骤和真实耗时。
- 设备页的本机知识状态、远端设备名称、连接阶段和失败信息。
- DSK 控制通道与数据通道到 `AppStateStore` 的事件驱动状态发布。
- 在线数量和可用设备数量的统一计算。

本次不扩展远端知识协议，不伪造远端知识类型、索引状态、同步时间或设备别名。

## 状态定义

远端设备的展示状态由真实的 `controlState` 和 `dataState` 共同决定：

| 条件 | 展示状态 | 是否可用于查询 |
| --- | --- | --- |
| 控制和数据通道均为 `READY` | 已连接 | 是 |
| 任一通道为 `FAILED` | 连接失败 | 否 |
| 数据通道为 `BINDING` | 正在绑定 | 否 |
| 任一通道为 `CONNECTING` | 正在连接 | 否 |
| 设备已发现但通道未建立 | 未连接 | 否 |

`activePeerCount` 表示控制和数据通道均为 `READY` 的远端设备数量。本机始终作为本地查询源，因此页面展示的可用设备总数为 `1 + activePeerCount`。

## 架构与数据流

`DskControlHub` 和 `PeerConnectionPool` 在状态发生变化时发送状态事件。`Task3TlsCoordinator` 汇总控制通道和数据通道事件，并通知 `AppRuntime`。

`AppRuntime` 保存最近一次发现的真实设备集合和每台设备的最近失败码，通过单一的状态发布方法重新构造 `PeerStatusSnapshot[]`。每次发现、开始连接、控制通道就绪、数据绑定、连接成功、失败或断开时，都更新 `AppStateStore`。

`Index` 已订阅 `AppStateStore`，因此无需 UI 轮询；快照更新后查询页和设备页会自动重绘。

## UI 行为

### 查询页

- 摘要显示真实的可用设备数量和连接概况。
- 查询范围始终包含本机，只追加当前真正可用的远端设备。
- 远端设备名称使用系统发现的原始名称；名称为空时使用脱敏设备 ID。
- 查询步骤不再写死“查询工作平板”。有实际来源名称时显示来源名称，否则显示“查询可用设备”。
- 删除每一步的 `00:01` 至 `00:05` 虚假耗时。
- 查询结束且 `totalTaskMs > 0` 时，仅显示真实总耗时。

### 设备页

- 本机不再固定标记为“手机”，名称显示为“本机”。
- 本机仅展示真实的索引状态、文档数量和分块数量。
- 删除固定的本机/远端知识类型和“最近同步：刚刚”。
- 删除把 `work`、`living` 映射为中文别名的逻辑。
- 远端卡片分别展示真实控制通道状态、数据通道状态和失败码。
- 不再用数据通道 `READY` 冒充远端索引已更新。
- 没有发现远端设备时显示真实空状态。

## 错误处理

- 设备发现失败继续通过现有 `AppError` 路径展示。
- 单台设备连接失败不会阻止其他设备状态发布。
- 失败码保留在对应设备快照中；新的连接尝试开始时清除该设备的旧失败码。
- 断开事件必须把设备从可用集合中移除，但保留其已发现信息并显示为未连接或连接失败。

## 测试策略

采用测试驱动实现：

1. 为纯状态映射函数编写失败测试，覆盖 `READY`、`CONNECTING`、`BINDING`、`FAILED` 和 `DISCONNECTED`。
2. 为在线数量和可用设备总数编写失败测试。
3. 为查询范围和动态查询步骤文本编写失败测试，证明不存在固定设备名称。
4. 为运行时状态投影编写失败测试，覆盖连接成功、失败和断开事件后的快照变化。
5. 运行相关 Hypium 测试和 `assembleHap`；若仓库已有测试编译问题仍存在，单独报告并以构建结果和针对性测试结果作为验证证据。

## 非目标

- 不修复 DSK 会话创建或 `onCollaborate` 本身的连接问题。
- 不新增远端知识档案或同步时间协议。
- 不修改查询路由、证据聚合和历史记录业务规则。
- 不引入定时器轮询连接状态。
