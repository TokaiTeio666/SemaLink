# SemaLink 自动路由查询与三页 UI 设计

## 目标

将 SemaLink 的主要使用方式改为“只输入问题，系统自动寻找最佳答案”。用户不需要预先选择设备，也不需要手动连接某台设备。系统把本机知识库与已发现的在线设备作为候选来源，根据问题和设备能力自动路由查询，汇总证据后返回答案。

本设计覆盖查询、设备、历史三页 UI，以及查询入口与现有语义路由/多设备协调模块之间的调用关系。现有通信层改动不在本设计中回滚或重构。

## 已确认的产品边界

- 查询页是默认首屏。
- 用户输入问题后直接提交，不选择设备、不选择发起端、不点击连接。
- 候选来源包含本机知识库和已发现的在线设备。
- 系统自动按语义匹配、资料覆盖、实时性、负载、隐私和延迟选择最佳来源。
- 高匹配来源可以并行参与查询；证据足够后提前收敛，不足时扩展查询范围。
- 设备页只负责展示和管理设备状态，不阻塞查询流程。
- 所有远端设备不可用时，自动回退到本机知识库。
- 没有足够证据时显示“证据不足”，不生成无来源的确定性答案。

## 用户流程

输入问题
  -> 创建查询任务
  -> 候选来源 = 本机知识库 + 已发现在线设备
  -> 自动计算设备匹配度
  -> 优先查询最佳来源，并行补充高匹配来源
  -> 汇总和校验证据
  -> 证据足够时生成答案
  -> 展示答案、可信度、来源和证据

查询结果记录原始问题、实际来源、参与查询的设备、可信度、证据状态、耗时以及失败原因或无结果原因。

## 页面结构

### 查询页

采用设计稿中间屏的结构，查询页不展示设备选择器。

- 顶部：SemaLink、菜单、通知。
- 在线状态条：显示在线设备数量，并提供进入设备页的入口。
- 主输入区：提示“询问所有可用设备中的资料”，包含问题输入框和发送按钮。
- 查询进度卡：理解问题、自动选择来源、查询相关资料、分析证据、生成答案。
- 结果卡：答案摘要、可信度、来源设备、查看证据、查看完整来源。
- 底部导航：查询、设备、历史。

视觉策略采用“答案优先 + 进度卡展开”：空闲时突出输入框；查询中展开自动路由过程；完成后突出答案、可信度和证据来源。

### 设备页

- 在线设备数量。
- 本机和远端设备列表。
- 每台设备的知识类型、索引状态、最近同步时间。
- 刷新和查看详情入口。
- 不提供“连接后才能查询”的阻塞式操作。

### 历史页

- 全部、成功、证据不足、无结果、设备离线筛选。
- 每条记录显示问题、来源、可信度和耗时。
- 点击记录可查看结果详情或重新查询。

## 模块与状态

保留现有通信、知识库和证据评估模块，调整调用关系如下：

- Index.ets：承载三页导航和页面展示，不再把选择角色或手动连接作为查询前置步骤。
- AppRuntime：提供统一的自动查询入口，初始化本机候选、使用已发现设备并启动语义路由。
- DeviceDirectory：维护本机和远端设备候选、知识领域、索引状态、负载、延迟与最近在线时间。
- DeviceSemanticRouter：输出最佳候选及评分明细。
- MultiDeviceTaskCoordinator：请求多个高匹配来源、汇总证据并判断充分性。
- AppStateStore：提供 UI 所需的查询过程状态，并继续保留现有语义任务字段。

UI 查询状态至少需要覆盖：IDLE、ROUTING、SEARCHING、ANALYZING、ANSWER_READY、INSUFFICIENT、FAILED。

现有 connectionState 可继续用于通信层和设备状态，但不能再作为“是否允许提交查询”的唯一条件。查询是否可提交应由问题内容、当前任务是否繁忙和知识路由是否可用决定。

## 数据流与回退

查询入口切换到语义任务协调器。提交后由本机和已发现设备形成候选集合，自动路由并执行查询。旧的单设备协议链路保留为兼容回退，不作为新 UI 的正常前置流程。

回退规则：

- 没有远端设备：查询本机知识库，并提示正在使用本机资料。
- 远端设备离线：跳过该设备，不阻塞查询；记录实际失败来源。
- 本机和远端都没有相关证据：显示证据不足，并列出已查询来源和缺少信息。
- 多个来源冲突：显示冲突提示，降低可信度，并允许查看各来源证据。
- 查询过程中重复提交：禁用发送按钮，支持取消当前查询。
- 查询失败：保留问题内容，提供重试，不清空历史记录。
- 知识库尚未完成初始化：输入区保持可见；提交时明确提示本机资料正在准备。

## 记录模型

历史记录不再以“本机发送给某台设备”为主要表达，而是记录一次自动查询任务：

- 原始问题。
- 状态：成功、证据不足、无结果、设备离线或失败。
- 参与查询的来源设备。
- 最佳来源及其路由评分（如可用）。
- 可信度、证据数量、冲突数量和耗时。
- 结果摘要及错误原因。

## 验证标准

功能验证：

- 不连接指定设备也能提交查询。
- 只有本机在线时可以查询。
- 多台设备在线时自动选择来源，并在结果和历史中展示来源。
- 设备离线后查询自动回退。
- 证据不足和来源冲突正确展示。
- 历史记录保存成功、失败、无结果和证据不足状态。
- 查询、设备、历史三页可正常切换。
- 不影响现有通信层、远端响应和知识库导入测试。

实现后应至少运行相关单元测试和 ArkTS 编译/构建检查；如能启动设备预览，再验证默认首屏、自动提交、查询中状态和历史记录展示。

## 范围控制

本轮实现聚焦自动查询入口、三页 UI、查询状态展示和历史记录映射。设备发现协议、知识库检索算法、证据评估规则和现有 TLS/数据通道协议不做无关重构；只有当现有接口无法支持自动查询入口时，才进行最小必要适配。
